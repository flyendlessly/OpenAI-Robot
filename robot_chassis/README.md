# 智能 AI 小车底盘子系统 (Robot Chassis Subsystem)

> **定位**：高可靠性移动底盘子系统（ESP32-S3 下位机驱动 + 串口通信中间件）。  
> **核心设计哲学**：**绝对解耦、契约先行、防御性安全设计**。

---

## 1. 为什么“先解耦、后关联”是完全正确的架构决策？

在机器人与嵌入式工程中，**“脑（树莓派/AI）”与“小脑（ESP32-S3/电机）”强行混在一起是最大的初学者陷阱**：

1. **确定性与硬实时（Hard Real-Time vs Non-Real-Time）**：
   - 树莓派运行 Linux 系统，受网络 IO、系统调度、多线程阻塞影响，属于**非实时系统**。如果由它直接打 PWM 控电机，延迟抖动会导致小车顿挫甚至失控。
   - ESP32-S3 搭载 FreeRTOS，任务调度精细到微秒级，负责闭环 PID、编码器计数、物理刹车。
2. **故障隔离与物理安全（Fail-Safe）**：
   - 如果大模型生成超时、网络断流或语音助手崩溃，小车底盘必须能够**自主刹车（Watchdog / 离线保护）**，绝不能依赖远端 AI 下达“停下”指令才停。
3. **分层验证与零硬件门槛测试**：
   - **下位机独立测试**：ESP32-S3 烧录后，用串口助手或 Python 测试脚本直接发包调试，无需启动大模型。
   - **上位机独立测试**：AI 助手开发 Tool 时，可以用虚拟串口 Mock 底盘，无需真实硬件在旁边跑来跑去。
   - **调测成熟后一键桥接**：主工程只需封装一个基于协议契约的 `RobotClient`，无缝接入 LLM Function Calling。

## 3. 分阶段实施路线图 (Milestones)

### 阶段 1：面包板与通信协议打通（当前手头资源即可完成）
* **硬件需求**：ESP32-S3 (N16R8) + 面包板 + 2 颗 LED（或板载 RGB）+ Type-C 数据线。
* **目标**：
  1. 烧录 `esp32_firmware/src/main.cpp` 到 ESP32-S3。
  2. 运行 `host_tools/serial_test.py`。
  3. 验证 JSON 协议解析、左右轮 LED 亮灭模拟调速、心跳超时自动灭灯保护。

### 阶段 2：动力底盘接入与闭环调速
* **硬件需求**：2WD 带编码器电机底盘 + TB6612FNG 驱动模块 + 2S 18650 锂电池盒 + 稳压电源。
* **目标**：
  1. 移植电机驱动库，输出 PWM 与方向控制。
  2. 实现编码器脉冲捕获与双轮速度 PID 闭环，确保走直线不跑偏。

### 阶段 3：底层物理防护与传感器融合
* **硬件需求**：ToF 测距模块 (VL53L0X) 或超声波 (HC-SR04)。
* **目标**：
  1. ESP32-S3 内部硬件级防撞中断：前方 < 15cm 时强制刹车并上报报警帧。
  2. 电池电压实时 ADC 采样与低电量告警。

### 阶段 4：桥接到 `my-openai-robot` 具身智能体
* **目标**：
  1. 在 `my_openai_robot/` 中新增 `robot_adapter.py`，实现 `RobotAction` 抽象层。
  2. 注册 LLM Tools（移动、旋转、避障查询、电量巡检）。
  3. 对接语音助手全双工管线：“小智，向前开一点” -> 语音意图识别 -> 小车物理移动。
