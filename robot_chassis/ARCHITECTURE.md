# 机器人底盘系统架构设计 (Architecture Blueprint)

## 1. 系统分层与职责边界 (Separation of Concerns)

系统严格划分为 **上位机认知层（Cognitive Layer / 大脑）** 与 **下位机执行层（Executive Layer / 小脑）**：

```text
+-------------------------------------------------------------+
|        上位机 (树莓派 / Linux / my-openai-robot)            |
|                                                             |
|   +-------------------+       +-------------------------+   |
|   | 语音流控 (ASR/TTS) |       |  大模型 (LLM / VLM)     |   |
|   +---------+---------+       +------------+------------+   |
|             |                              |                |
|             v                              v                |
|   +-----------------------------------------------------+   |
|   |          具身智能体 (Embodied Agent 规划中枢)        |   |
|   +--------------------------+--------------------------+   |
|                              |                              |
|                              v (Tool Call)                  |
|   +-----------------------------------------------------+   |
|   |         Chassis Adapter (小车适配器 Client)         |   |
+---+--------------------------+------------------------------+
                               |
                   USB / UART 串口 (统一 JSON 协议)
                               |
+---+--------------------------v------------------------------+
|        下位机 (ESP32-S3 N16R8 / FreeRTOS / 小脑)            |
|                                                             |
|   +-----------------------------------------------------+   |
|   |         Protocol Parser (帧解析与合法性校验)        |   |

|                              |                              |

```

## 2. 核心架构原则

### 2.1 防御性安全原则 (Defensive Safety & Fail-Safe)
下位机绝不无条件信任上位机。下位机具备独立的硬安全保护逻辑：
1. **通信断连超时保护（Watchdog Timer）**：
   - 上位机每次下发的移动指令都必须携带 `time_ms`（最大执行时间）。
   - 如果发生串口掉线或上位机崩溃，ESP32-S3 定时器超时后**立即切断电机 PWM**，防止小车无限狂奔。
2. **硬件级紧急避障（Hard Bump Prevention）**：
   - 测距传感器（ToF / 超声波）的死区判定（例如前方 < 15cm）在 ESP32-S3 本地循环中以最高优先级执行。
   - 触发时强制制动，并向上位机主动推报警事件包，覆盖上位机的移动指令。

### 2.2 协议非对称设计 (Asymmetric Communication)
- **指令采用“请求-即时确认”模式**：上位机下发指令，下位机收到后立即返回 ACK（已接收校验通过）或 NACK（参数超限）。
- **执行完成采用“事件通知”模式**：小车走完指定距离或触发刹车后，上报 `DONE` 或 `ABORT` 事件。
- **状态采用“低频遥测流”模式**：ESP32-S3 以固定频率（如 5Hz~10Hz）主动上报当前电压、轮速与传感器距离，上位机只缓存最新状态，无需主动轮询。

## 3. 状态机模型 (Chassis State Machine)

下位机内部维护一个简明严格的状态机：

```text
       +--------------+
       |   BOOTING    |
       +-------+------+
               | 初始化完成
               v
  +--------> READY <---------+
  |            |             | 移动结束 / 手动停止
  |            | 接收运动指令 |
  |            v             |
  |         MOVING ----------+
  |            |
  |            | 发生异常 (超时 / 障碍物阻挡 / 低电压)
  |            v
  +-------- STOPPED (ALARM)
```

- **BOOTING**：GPIO 初始化、PWM 归零、传感器自检。
- **READY**：静止待命，接收指令，维持低频心跳。
- **MOVING**：电机使能输出，闭环 PID 调整，持续检测前向测距与超时。
- **STOPPED (ALARM)**：制动锁止，蜂鸣器/LED 警报，等待上位机确认或环境恢复。

## 4. 与主项目 `my_openai_robot` 的集成契约 (Future Integration)

当 ESP32-S3 下位机与小车硬件调测完毕后，与主项目的集成将遵循 **“适配器模式 (Adapter Pattern)”**，对主业务零侵入：

1. **接口层**：在主工程中创建 `my_openai_robot/tools/chassis_tool.py`。
2. **抽象契约**：
   ```python
   class ChassisController:
       def move(self, direction: str, distance_cm: float, speed_pct: int = 50) -> bool: ...
       def turn(self, angle_deg: float, direction: str) -> bool: ...
       def stop(self) -> bool: ...
       def get_telemetry(self) -> dict: ...
   ```
3. **注册给 LLM**：将上述方法直接转换为 OpenAI Function Calling Tool Schema，LLM 即可自主控制底盘。
4. **单元测试与 CI 友好**：上位机开发时无需连接真实小车，直接切换到 `MockChassisController` 即可跑通自动化测试。
